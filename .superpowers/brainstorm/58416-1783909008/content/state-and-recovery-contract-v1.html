设计第 5 部分：谁保存什么，失败后怎么恢复

核心原则：Hermes 负责对话与推理，平台负责可审计的工作记录，研究产物继续由既有后端仓库负责。页面只做投影，不创造第二套业务事实。

A. 三层真相源：明确归属，禁止互相覆盖
对话真相

Hermes Session

消息上下文、推理会话、工具请求、实际 provider / model。

平台不修改 Hermes 历史，也不伪造 provider。
↔
工作台真相

Platform Ledger

会话映射、每轮 Run 状态、幂等键、可恢复事件、结果链接。

这是控制面账本，不复制因子、回测或审批正文。
→
业务真相

Existing Repositories

因子、回测、实验、日报、候选源码、Gate 与 promotion diff。

结果页按稳定 ID 读取原产物，不把聊天总结当结果。
B. 平台只新增一份“小账本”
Session

平台 session ID ↔ Hermes session ID；锁定 provider / model；标题与最后活动时间。

Run

一条用户消息对应一个 Run；保存 client_request_id、Hermes run ID、状态、实际 provider、错误码。

Event

仅持久化白名单事件和 sequence cursor，供刷新/断线续传；原始敏感日志不入库。

Result link

只记录 artifact kind + stable ID + repository；结果正文仍在原仓库。

明确不做：localStorage 当数据库；把聊天 Markdown 当回测结果；另建一套“候选审批状态”。
C. 一个 Run 的可恢复状态机
queued→ running→ awaiting approval→ running→ completed

任何非终态都允许：

failed
明确错误与可重试性
stopped
用户停止，保留已完成产物
interrupted
连接中断，先对账再重试
关键约束：同一 session 同时最多一个活跃 Run；同一 client_request_id 永远不会重复提交；恢复时先查询 Hermes 真实状态，不能凭前端猜。
D. 用户看到的是可行动的降级，而不是假成功
Hermes 离线

今日概览和既有研究结果仍可读；历史对话显示平台审计投影；新对话与新研究禁用，不回退旧 AgentRunner。

SSE 断线 / 页面刷新

用 event cursor 重连并补齐缺口；若状态不确定标记“正在对账”，绝不自动重复执行。

Provider 配额或模型失败

展示实际 provider / model、失败原因和是否发生显式 fallback；不得显示虚构的剩余额度。

审批已过期 / 候选已变化

重新读取 canonical candidate、hash 与 Gate 状态；旧批准不能套到新内容，要求重新审阅。

部分结果已生成

保留并标注已完成产物，但整体 Run 为 stopped / failed；不能把局部产物包装成完整成功。

数据库不可用

禁止创建需要持久化的新 session / Run；既有业务产物继续按各自仓库的既定降级策略只读。

最小但必要的新增：在平台 PostgreSQL 增加工作台 Session / Run / Event / Result-link 控制面表；聊天的业务上下文仍归 Hermes，因子、回测、实验与审批仍归现有仓库。

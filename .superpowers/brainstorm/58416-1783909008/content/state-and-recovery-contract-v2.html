设计第 5 部分：谁保存什么，失败后怎么恢复

复核后的核心原则：Hermes、HQA、平台各自只拥有自己的真相；BFF 和前端只缓存、映射和展示，不能成为第四套业务事实。

A. 三个真相源 + 一个明确标记的只读投影
对话真相

Hermes Session

消息上下文、Hermes Run、原始事件、实际 provider / model。

平台不改写 Hermes 历史，也不伪造配额或 provider。
编排真相

HQA Research Task Ledger

结构化研究计划、plan hash、步骤、Run attempts、Gate refs、结果 refs 与派生阶段。

聊天消息不是任务状态；一个任务可跨多轮、多个 Run 和数日审批。
领域真相

Platform Repositories

因子、回测、实验、日报、候选源码、review locks 与 promotion diff。

结果页按 stable ID 读取原产物；Hermes 总结不等于成功结果。
BFF / PostgreSQL / UI 投影：只保存 session 映射、幂等键、白名单事件、最后同步时间与离线 transcript 快照；所有缓存必须带 last_synced_at / stale，可删除重建，绝不能用于通过审批或判断研究成功。
B. 研究 Task 与短生命周期 Run 分开
draft→ 待计划确认→ ready→ running
待领域 Gate→ 新 attempt → running→ completed
关键：Gate 1/2/3 可能等待数小时或数日。当前 Hermes Run 在阶段结束时终止，Task 保持“待领域 Gate”；批准后创建新 attempt，不让一个 Run 跨夜悬挂。
重试不改写旧 Run。失败 attempt 永久保留；新 attempt 使用相同 task_id、递增 attempt，并重新校验 plan / target digest。
C. Hermes Run 的可恢复状态机
queued→ running↔ 命令审批→ stopping
succeeded
阶段成功，不等于整个 Task 完成
failed
错误与 retryable 明示
stopped
保留已发布的部分产物
幂等：(session_id, client_request_id) 唯一；工具步骤使用 operation_id = hash(task, plan, step, inputs)。超时先对账，禁止盲目重发。
断线：每个白名单事件有稳定 event_id + cursor；重连后先取 Hermes Run snapshot，再补齐事件。SSE 断开绝不等于失败。
D. 两类审批绝不混在一起；全部绑定内容摘要
Hermes 命令审批

绑定规范化 command + args + working_dir hash，短 TTL、一次性；只允许这次工具调用，不能替代 Gate 1/2/3。

研究领域 Gate

Gate 1 绑定 formula / plan hash；Gate 2 绑定 candidate metadata + source digest；Gate 3 绑定 base commit + promotion diff digest。

已确认的现有风险：

当前 candidate approval 只证明某个 ID 被批准；同一 ID 的源码仍可被重写，promotion 又读取当下源码。新工作台上线前必须让 review lock 记录源码摘要，并在一次性回测和 promotion 时重新校验；摘要不同返回 stale，要求重新审批。

E. 用户看到的是可行动的降级，而不是假成功
Hermes 离线

平台结果、HQA Task 与带“上次同步”标记的 transcript 缓存可读；禁用新消息、新研究和命令审批；不回退旧 AgentRunner。

SSE 断线 / 调用超时

显示“重连/对账中”；outcome unknown 时按幂等键查询，不能自动重复执行。

Provider 配额或模型失败

展示 requested / actual provider、失败原因和显式 fallback；用户没预先接受的 provider 不得静默启用。

审批过期 / 目标变化

服务端重新读取 canonical target 并比较 digest；过期、已决或摘要不同一律 stale，刷新后重审。

只有部分产物

有合法 artifact + limitations 才可 completed_degraded；无可验证产物就是 failed，不能用聊天总结补成功。

账本或缓存不可写

会创建产物或审批的操作 fail closed；既有领域产物仍按原仓库策略只读。

首版落点：新增 HQA append-only research task ledger；平台 PostgreSQL 仅做可重建的 bridge/session 投影和离线缓存，不新建一套因子、回测、实验或审批真相。

## 为什么必须重排

2026-07-07 计划的产品方向仍成立，但平台在 brief、PostgreSQL paper account、
repository factory 和 `/hermes` 只读骨架阶段已经改变了接口事实。逐项复核后，旧计划
存在以下阻断：

- `ops-status` 和对应 GET 名义上是查询，实际会 reconcile pending sleeve，并可能
  finalize/discard 文件；这是现存安全缺口，应优先于新 UI 或员工扩容。
- 旧 account JSON、provider 调用、signal 字段和 paper repository 用法已漂移；照抄会
  绕过当前 file/mirror/canonical 事实源。
- prediction ledger 缺少锁、幂等和交易日规则；missed-opportunity 还没有可关联的
  signal/decision/action identity；market-foresight 员工主体则没有进入旧交付清单。
- cron、notify 和 Hermes artifact 消费没有形成真实端到端验收。

因此裁决是 **ACCEPT-AFTER-REPLAN**：接受目标，拒绝原样执行。

## 已完成 Slice 9C — 组合风险 v1（只使用统一 snapshot）

### 用户可观察目标

- 同时显示 position 对账户 equity 的占比与其在 invested/gross book 内的占比。例如
  top1 可以是已投资资金的 100%，但只占账户权益 0.03%；两者都必须呈现。
- account missing、cash-only、fallback/stale、malformed/command failure 必须是不同状态，
  解析失败绝不能伪装成“没有账户”。

### 事实与公式裁决

- 9C 只读 snapshot 已给出的 `market_value`；不重新调用行情、历史价格或平台
  `RiskEngine`，也不读取 account JSON/Parquet/PostgreSQL audit snapshot。
- `long = Σ max(market_value, 0)`；`short = Σ abs(min(market_value, 0))`；
  `gross = long + short`；`net = long - short = Σ market_value`。旧计划的
  `net = gross - cash` 量纲/语义错误，明确拒绝。
- `gross/equity`、`net/equity` 仅在 finite 且 `equity > 0` 时计算；否则保留美元敞口，
  比例为 null 并标 degraded。
- 集中度以 `abs(market_value) / gross` 为 invested-book 权重：top1、top3、HHI。
  snapshot 的 `position.weight` 是 account-equity 权重，只用于并列展示，不能直接算 HHI；
  artifact 同时给出按 `market_value/equity` 重算值和一致性，漂移时降级而非静默选边。
  `gross == 0` 时集中度是 `not_applicable/null`，不是 0。
- `avg_cost_fallback` 可参与明确标注的 estimated exposure，但整体 degraded；不可称为
  current market valuation。repository `stale/warnings/reconciliation` 原样保留。
- 逐仓保留 `price_kind/price_as_of`。只有带时区 timestamp 才计算 age fact；无时区不猜
  UTC/本地时区。9C 没有 freshness/concentration policy threshold，因此
  `policy_evaluation=not_evaluated`，不得擅自判定 stale 或 breach。
- pending orders 不计入 current exposure，只记录数量并声明 projected exposure 未建模。
- 金额使用 snapshot 的 `base_currency` 显式标注；9C 不做 FX 换算。

### Artifact 状态与稳定合同

- `available`：账户存在且当前敞口可完整计算；cash-only 也属于可准确观察的 available，
  但 concentration 为 not applicable，不能写“零风险”。
- `degraded`：fallback 估值、repository stale/warning、非正 equity、缺失/非法关键
  provenance 等导致结论只可部分信任；reason code 与平台 warning 均保留。
- `not_applicable`：file/mirror 明确返回 `account_exists=false`；读取不得创建账户。
- `unavailable`：CLI 非零、canonical bootstrap/database/storage error、JSON 或合同非法；
  暴露稳定 error code，不输出部分合计。
- 所有数字必须 finite，JSONL 使用 `allow_nan=False`；positions 按绝对市值降序、symbol
  次序确定性输出。stdout 只从已生成 artifact 渲染，避免两套计算漂移。

### 深模块与公开 interface

新增 `hqa.predictions.PredictionLedger` 深模块，调用方只学习三个行为：

1. `create(request)`：校验请求、读取已完成 session 的 entry evidence，在独占锁内分配 ID
   并 append `prediction_created`，返回完整 open state。
2. `list(status=None, since=None)`：严格折叠事件为当前 state；只读、零行情调用、零写入。
3. `reconcile_due(as_of=None, limit=25, cursor=None)`：锁外读取每条 due 预测的严格历史
   证据，锁内重新读取并以 CAS 方式 append 至多一个 `prediction_scored`；返回逐 ID report
   和稳定游标，避免旧失败项长期占满一页、饿死后续预测。

价格读取是内部真实 seam：production adapter 复用 9D
`quant_cli.run_historical_prices()`，测试使用 in-memory adapter。不得额外创建浅的
repository/price-series 转发层，也不修改 `ai-quant-platform`。

### 预测与评分合同

- 首版固定 `subject_kind=us_equity`、plain uppercase US symbol、`direction=up|down|flat`。
  `confidence` 明确定义为“所选方向正确”的概率，finite 且在 `[0,1]`；因此
  `direction_brier=(confidence-int(direction_correct))²` 是二元正确性 Brier，不冒充完整
  三分类概率 Brier。
- `falsifier` 必填但只做人读证据，`rationale` 可选；代码不解释自然语言，也不由其自动
  判分。`flat_threshold_pct` finite、positive；实际收益落在正负阈值内才是 flat。
- 可选 `range_low/range_high` 必须成对、positive、finite 且 low < high。创建时用同一 entry
  close 固化为 `range_return_low/high`；评分只输出独立 `range_hit`，拒绝旧模板在区间外
  实际恒为 0 的“线性衰减分”。
- created event 保存当时 entry close/provenance；scored event 必须重新用**同一份** Futu/QFQ
  payload 同时读取原 entry session close 与 outcome close，再计算 return，避免公司行动后
  把两次不同调整尺度的 close 相除。两份 entry close 都保留，QFQ restatement 只陈述事实。
- 每个 ID 恰好一个 created、最多一个 scored，revision 只能 `1 → 2`。重复 reconcile 若
  已 scored，不再取价/append；并发 race 在 commit 锁内变成 `already_scored`。若未来 QFQ
  修订与冻结分数冲突，不静默重算；rescore/override 另立计划。

### 时间、session 与窗口规则

- `created_at/scored_at` 必须 timezone-aware，落盘规范为 UTC `Z`；日期严格
  `YYYY-MM-DD`。market timezone 固定 `America/New_York`。
- completed-session cutoff 固定为 `as_of` 转 New York 后的 calendar date 减一天；不猜
  当日是否已提前收市，也不读取未完成 daily bar。create 在 cutoff 前回看并选最新实际
  Futu row，周末/节假日自然落到最后一个真实 session。
- `horizon_date` 是 calendar anchor，不声称本身一定是交易日；reconcile 选择
  `session_date >= horizon_date` 的第一条实际 Futu row。尚无 completed row 是
  `not_ready`，provider/contract 失败是 `unavailable`，两者都保持 open。
- 为让 scoring 的 entry→outcome 证据始终落在平台 500-inclusive-day guard 内，
  `horizon_date` 最多距 entry session 489 calendar days；outcome resolution 最多向后观察
  10 calendar days。

### JSONL、锁与失败语义

- `entries.jsonl` 每行是完整有限 JSON event：拒绝 duplicate key、NaN/Infinity、非法
  Unicode、torn tail、未知 schema/event、重复 created/scored、scored-before-created。
  读取遇坏账必须 `prediction_ledger_corrupt` fail closed，不能静默跳行或 last-wins。
- 本机 POSIX 文件系统用稳定 `.ledger.lock` + `fcntl.flock`；读拿 shared、create/score
  拿 exclusive，并有有限 lock timeout。ID 在同一 exclusive lock 内按 UTC created date
  的最大 sequence +1 分配，不能按 `len()`。事件预先 `allow_nan=False`/UTF-8 校验，再
  `O_APPEND` 完整写入并 fsync 文件和目录；短写/ENOSPC 回滚到原始长度，不能确认回滚时
  返回非重试的 `prediction_durability_unknown`。
- 网络行情读取绝不能持有 exclusive lock。batch reconcile 以“每个 prediction event 原子”
  为界；中途崩溃后重跑只补剩余 open 项。
- stable errors 至少区分 invalid request、entry price unavailable、history/provider unavailable、
  not ready、ledger busy、ledger corrupt、I/O failure 与 durability unknown。
